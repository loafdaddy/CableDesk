# ADR-005: Native RPM packaging, no Flatpak/Snap/AppImage

## Status

Accepted, partially implemented (spec written, not build-tested — see
`docs/OPEN_QUESTIONS.md` #20).

## Context

The project's own requirements rule out Flatpak, Snap, and AppImage for the
initial version, and the user is comfortable with terminal-based,
native-package-manager installation. CableDesk also needs system-level
integration (systemd services, Polkit actions, firewalld zones, kernel
module loading) that sandboxed packaging formats actively resist — Flatpak
in particular is documented as incompatible with Sunshine's KMS capture
backend (`docs/UPSTREAM_INTEGRATION.md` §2).

## Decision

Ship native RPM packages for Fedora first (`packaging/fedora/
cabledesk.spec`), following Fedora's `rust-srpm-macros`/`cargo-rpm-macros`
conventions rather than a hand-rolled `cargo build` invocation, with a
vendored-dependency build (`%cargo_prep -v`, `bundled(crate(...))`
Provides) rather than per-crate Fedora packaging of the full dependency
tree — see `docs/PACKAGING.md` §1.2 for why the vendored path is the
pragmatic choice for an application (not library) with this many
dependencies, even though Fedora's guidelines treat full vendoring as a
last resort in general.

Subpackage split: `cabledesk` (GUI + desktop/metainfo), `cabledesk-agent`,
`cabledesk-helper`, `cabledesk-selinux` (currently empty placeholder) —
matching the privilege-separated process architecture in
`docs/ARCHITECTURE.md`. `-debuginfo`/`-debugsource` are auto-generated by
`rpmbuild`, not hand-written.

## Consequences

- The spec requires `rust-packaging >= 25` (the version that added
  vendored-build macro support) and pins GTK4/libadwaita minimum versions
  matching what this milestone was actually built and tested against
  (4.14/1.4 as conservative floors; the dev machine had 4.22/1.9).
- Changelog convention is a conventional hand-written `%changelog`, not
  `%autochangelog` — because whether CableDesk ultimately builds through
  Fedora's dist-git+koji pipeline (where rpmautospec is the current
  default) or ships as a standalone COPR/self-hosted project is undecided
  (`docs/OPEN_QUESTIONS.md` #19), and `%autochangelog` only works in the
  former.
- Debian/Ubuntu/Arch/openSUSE packaging is explicitly deferred to Phase 6
  (`docs/ROADMAP.md`) — placeholder READMEs exist under `packaging/` but
  no working packaging.
- The spec has not been build-tested (`rpmbuild`/`rpmlint` were not
  installed in this milestone's environment, and installing them wasn't
  done without asking first) — see `docs/OPEN_QUESTIONS.md` #20 for the
  concrete next step.
- Several Fedora Rust/Packaging Guidelines pages were inaccessible to
  automated research (anti-bot protection) — the spec's macro usage should
  be diffed against a direct human read of
  `docs.fedoraproject.org/en-US/packaging-guidelines/Rust/` before this ADR
  is considered fully verified (`docs/OPEN_QUESTIONS.md` #14).
